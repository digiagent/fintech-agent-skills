# Repository Rules

## Skill conventions

- Store each skill at `skills/<skill-name>/`.
- Use kebab-case names.
- The directory name must exactly match `name` in `SKILL.md` frontmatter.
- Every skill requires `SKILL.md` in its root.
- Keep core instructions concise and operational.
- Put detailed material in `references/`.
- Put output skeletons and editable artifacts in `assets/`.
- Put evaluation prompts and expected behavior in `evals/`.
- Never add secrets, private keys, seed phrases, production credentials, customer data, private investor data, or non-public business metrics.

## Quality rules

- Separate confirmed information from assumptions.
- Never fabricate current funding opportunities, dates, legal status, security results, or on-chain evidence.
- Do not claim legal compliance, regulatory approval, security certification, or investment outcomes.
- Require verification for live data, deadlines, balances, transactions, and program availability.
